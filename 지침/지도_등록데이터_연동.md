# 지도와 등록 식당·메뉴 연동

> 2026-10-25 후속 구현: 아래는 ZIP에 있던 기존 프론트 집계의 기록이다. 현재 일반 파티는 `../dimigo_Hackathon-main/server/`의 SQLite 등록 자료와 API로 연결했으며, 지도 개수는 소비자용 `/api/v1/restaurants/nearby-count`로 조회한다. 후보 생성·식사 제한·권한·주문 금액은 서버가 검증한다. 최신 상태와 남은 운영 항목은 [구현 결과](../dimigo_Hackathon-main/docs/IMPLEMENTATION.md)를 따른다. 원본 카카오 SDK와 개발용 샘플 경로는 유지했다.

## 현재 구현

- 카카오 지도 SDK는 지도 표시와 약속 장소 검색에 사용한다. 카카오 음식점 카테고리 검색으로 식당 수나 메뉴 후보를 만들지 않는다.
- 검색 반경은 200~1000m, 10m 단위 슬라이더다. 지도 원과 등록 식당 필터가 같은 값을 사용한다. 저장된 기존 범위 초과 값도 이 범위로 보정한다.
- 선택한 중심 좌표부터 직선거리가 반경 이하인 등록 식당을 중복 없이 센다. 이 수는 예산 적용 전 등록 식당 수다. 메뉴가 없으면 메뉴 후보는 0개일 수 있다.
- 음식 후보는 해당 반경 안 등록 식당에 연결된 `AVAILABLE` 메뉴 중 예산 이하인 메뉴만 음식 카테고리로 묶는다. 카테고리별 가격대와 식당 수를 등록 메뉴에서 집계한다.
- 품절·숨김 메뉴, 등록되지 않은 식당의 메뉴, 카테고리가 없는 메뉴는 후보에 들어가지 않는다. 결과가 없을 때 기존 메뉴 목록으로 대체하지 않는다.
- 파티 생성/조건 수정 시 후보 스냅샷을 저장한다. 조건 수정 시 변경된 후보 밖의 열람·소거 기록은 화면 집계에서 제외한다.

관리자/사업자 등록 화면은 있다고 가정한다. 이번 변경은 등록 화면이나 서버를 구현하지 않는다.
현재 `src/data/registeredCatalog.ts`는 등록 완료 결과를 흉내 낸 시연 데이터다. 서울시청/와동공원 인근의 가상 식당이며 실제 제휴·영업 정보가 아니다.
`src/lib/registeredCatalog.ts`는 등록 목록에 대한 거리·가격·판매 상태 필터와 카테고리 집계를 담당한다.
기존 `/dev/sample-party/menu`는 명시적인 개발용 샘플 경로로만 유지한다.

## 제공된 API 계약과 연결할 부분

- 등록 원천: `POST /api/v1/merchant/restaurants`, `POST /api/v1/merchant/restaurants/{restaurantId}/menus`
- 파티 저장: `POST /api/v1/parties`, `PATCH /api/v1/parties/{partyId}`의 `location`, `searchRadiusMeters`, `budgetPerPerson`
- 음식 후보: `POST /api/v1/parties/{partyId}/category-candidates/generate` → 작업 완료 확인 → `GET /api/v1/parties/{partyId}/category-candidates`
- 음식 후보 카드: `category`, `nearbyRestaurantCount`, `priceRange`
- 메뉴 판매 상태: `AVAILABLE`, `SOLD_OUT`, `HIDDEN`

현재는 실제 API 서버 주소와 인증 정보가 제공되지 않아 위 요청을 전송하지 않는다. 등록 원천과 집계 구조만 맞추었다.
현재 API 초안의 100~5000m 범위 안에서 사용자 화면을 200~1000m로 제한한 것이며 기존 OpenAPI 계약을 변경하지 않았다.

## 서버 연결 전에 필요한 추가 계약

파티 생성 전 지도 화면에서 사용할 **등록 식당의 반경별 개수 미리보기** API는 현재 목록에 없다.
중심 위경도와 `searchRadiusMeters`를 받아 등록 식당 수를 반환하는 소비자용 계약을 백엔드와 확정해야 한다.
사업자 전용 목록 API는 본인 매장 관리용이므로 일반 사용자 지도 조회에 사용하지 않는다.
현재 클라이언트 집계는 시연용이다. 실제 서비스에서는 등록 원천, 가격, 판매 상태, 식사 제한과 후보 생성 권한을 서버에서 검증해야 한다.
