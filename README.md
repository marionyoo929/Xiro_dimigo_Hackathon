# 시로 XIRO

React + TypeScript + Vite 사용자·사업자 웹과 Express + SQLite API입니다. Node.js **24 이상**이 필요합니다.

이 폴더가 Git 저장소 루트이자 실제 실행 폴더입니다. 중첩 폴더로 들어가지 않고 아래 명령을 실행합니다.

## 개발 실행

```powershell
npm.cmd ci
npm.cmd run dev
```

[로컬 앱](http://localhost:5173)에서 사용합니다. Vite(5173)와 API(3001)가 함께 실행됩니다. API는 Vite의 `/api` 프록시를 통해 같은 출처로 접근합니다. `npm run preview`는 정적 빌드 확인 전용이며 API를 실행하지 않습니다.

개발 실행은 **시연 모드**입니다. 닉네임으로 시작하거나 사장님 시연 버튼을 사용하세요. 실제 SNS 로그인은 제공하지 않습니다. 안산 중앙역 주변 식당 7곳과 확인된 메뉴 90개가 `data/demo.sqlite`에 등록되어 있습니다. 기존 삼겹식당·봉구스밥버거는 유지하고 포크너·히또시·30센치옛날수제왕돈가스·소담촌·춘천명물닭갈비막국수를 추가했습니다. 사장님 화면에서 등록/수정한 내용은 서버 DB에 반영됩니다.

Git에는 실행 중인 DB·로그인 세션·개인 정보를 포함하지 않습니다. 새로 받은 프로젝트는 첫 `npm run dev` 실행 때 공개 카탈로그의 식당·메뉴와 최근 30일 통계 자료를 자동으로 생성합니다. 이후 재시작은 기존 등록/수정 내용과 주문을 유지합니다. 발표 준비용 [개발 예상 질문과 답안](docs/발표_개발_예상질문.md)도 제공합니다.

지도 키가 없어도 **안산 중앙역 1번출구** 바로 선택 버튼으로 전체 흐름을 진행할 수 있습니다. 카테고리는 파스타·라멘·돈가스처럼 기본 음식명으로 묶습니다. [등록 자료와 출처](docs/CATALOG_SOURCES.md)에 확인일·사진 범위·재등록 방법을 기록했습니다. 기존 개발 화면 샘플은 `/dev/sample-party/menu`에 있습니다.

## 시연 순서

1. 방장: 닉네임 시작 → 만 나이·성별 저장 → 파티 만들기 → 장소 검색 또는 지도 클릭·핀 이동 → 상세 만날 위치·반경·예산·약속 시간 선택 → 파티 생성. 기본 정보는 한 번 저장하면 유지되고 홈에서 수정할 수 있다. 초대·QR 주문 게스트도 처음에 입력한다.
2. 대기실에서 초대 링크 복사. 별도 브라우저/휴대전화에서 링크를 열어 게스트 참가.
3. 각자 식사 제한을 저장하고 최신 제한 확인. 방장이 음식 후보 생성.
4. 카드를 충분히 보거나 확인 버튼을 눌러 확인하고 싫은 후보를 왼쪽으로 밀어 소거. 확인 기록이 서버에 저장된 뒤 전원이 검토 완료 → 방장 음식 확정. 저장 실패 시 화면에서 재시도한다.
5. 식당 후보 생성 → 전원 검토 완료 → 방장 확정·최종 식당 선택.
6. 별도 브라우저에서 사장님 시연 시작 → 선택 식당의 QR 발급. 방장은 **카메라로 매장 QR 스캔**을 눌러 QR을 비추면 현재 파티에 연결된다. 홈의 **매장 QR 스캔**에서는 일반 주문 또는 해당 매장의 파티 연결로 이동한다.
7. 각자 메뉴·수량·옵션 선택 → 내 선택 완료 → 방장 주문 제출.
8. 사장님 주문 화면에서 전체 수락/거절. 사용자 화면에 상태와 거절 사유 반영. 수락 시 수수료 근거는 요율 미정의 계산 대기로 생성.
9. 사장님 `통계`에서 최근 3일·일주일·한 달의 매장 주문 추이, 전체 가게 인기 카테고리, 우리 음식이 소거된 모임에서 살아남은 다른 카테고리, 고객 연령대·성별 구성을 확인한다. 다른 가게 이름이나 개인 정보는 표시하지 않는다.

통계 자료를 다시 채우려면 `npm.cmd run stats:seed -- --apply`를 실행한다. 최근 30일 자료를 만들고 기존 자료는 자동 백업한다. 기존 주문 접수 목록에는 섞이지 않으며 일반 운영 API에서는 집계하지 않는다. API 코드를 변경한 뒤에는 실행 중인 `npm run dev`를 한 번 재시작해야 한다.

파티 없이 QR을 스캔하거나 QR 링크를 열면 일반 QR 주문을 시작할 수 있습니다. 앱 안에서 결제하지 않습니다. 스캔은 브라우저 안에서 처리하며 닫기·인식 완료 시 카메라를 종료합니다. 실시간 카메라는 HTTPS 또는 localhost에서 사용합니다. 카메라를 사용할 수 없으면 스캔 화면의 **QR 사진 선택**으로 촬영·저장한 QR을 읽을 수 있습니다.

## 지도와 여러 기기

Vite의 `envDir`는 프로젝트 루트(`.`)입니다. `.env.example`을 참고해 `package.json`과 같은 폴더의 `.env.local`에 지도 키를 둡니다. `.env.local`과 실행 DB는 Git에 포함하지 않습니다.

```env
VITE_KAKAO_MAP_APP_KEY=카카오_JavaScript_키
```

카카오맵 사용 설정과 JavaScript SDK 도메인에 접속 출처를 등록해야 합니다. 로컬 기본 출처는 `http://localhost:5173`입니다. LAN/운영 도메인도 별도로 등록합니다. 지도 설정 변경 후 개발 서버를 재시작하세요.

Vite는 `0.0.0.0`에 바인딩합니다. 같은 네트워크의 휴대전화에서 PC의 LAN 주소와 5173 포트로 접속하세요. PC 방화벽에서 해당 로컬 접속이 허용되어야 합니다. 링크 복사·QR 이미지는 브라우저의 현재 출처로 생성되므로 PC에서 공유할 때도 LAN 주소로 앱을 열어 두세요. HTTPS가 없는 LAN에서는 복사 기능이 제한될 수 있어 읽기 전용 링크 입력칸도 제공합니다.

## 검증

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run test:e2e
```

API 통합 테스트는 별도 메모리/임시 SQLite DB를 씁니다. E2E는 설치된 Google Chrome을 사용하며 별도의 5174/3002 포트·임시 DB에서 실행합니다. 결과와 스크린샷은 `test-results/`에 저장합니다. 실제 카카오 SDK 요청은 E2E에서 차단하므로 지도 현장 검증과 구분합니다.

원본 80개 API 계약은 `docs/openapi.yaml`입니다. 추가 미리보기·로컬 인증 계약은 `docs/api-extensions.yaml`입니다. `npm run generate:types`로 프론트 타입을 다시 만듭니다.

## 운영 실행과 계정 발급

이 브랜치는 해커톤 시연용입니다. `npm run dev`와 `npm start` 모두 `NODE_ENV`와 관계없이 시연 모드로 실행하며, 게스트 시작·사장님 시연 로그인과 샘플 데이터를 제공합니다. 기본 DB도 동일한 `data/demo.sqlite`를 사용합니다.

프로젝트 폴더(package.json 옆)의 `.env.local`에 서버 설정을 둡니다. 지도 환경 파일은 위 설명대로 상위 폴더입니다.

```env
NODE_ENV=production
PUBLIC_ORIGIN=https://서비스_도메인
API_HOST=0.0.0.0
API_PORT=3001
LOCAL_AUTH_ENABLED=true
MAX_MEMBERS=8
# DB_PATH=영구_볼륨의_SQLite_절대경로
```

```powershell
npm.cmd run create:user -- owner@example.com 사장님 --merchant
npm.cmd run create:user -- user@example.com 사용자
npm.cmd run build
npm.cmd start
```

비밀번호는 숨김 프롬프트에서 입력합니다(12자 이상). 자동화에서는 `XIRO_ACCOUNT_PASSWORD` 환경변수를 해당 명령에만 제공할 수 있습니다. 계정 역할은 서버 운영자가 발급합니다. 로컬 로그인은 이메일/비밀번호 검증 후 60초 단일 사용 코드를 명세의 로그인 API와 교환합니다. 공개 회원가입·복구·SNS 연결은 후속 운영 결정입니다.

TLS 프록시는 `/api`와 정적 경로를 이 서버로 전달하고 SSE buffering을 꺼야 합니다. `docs/nginx.conf.example`을 참고하세요. SQLite는 단일 Node 프로세스·영구 로컬 볼륨용입니다. 수평 확장 전에 공유 DB/작업 큐/rate limit/접속 상태 구성을 바꿔야 합니다.

```powershell
npm.cmd run backup
```

SQLite 온라인 백업은 `backups/`에 시간별 새 파일을 만듭니다. 백업 주기·접근 권한·보관 기간·복원 검증은 운영 환경에서 설정해야 합니다. DB와 백업은 Git에서 제외됩니다.

[구현 결과와 남은 운영 작업](docs/IMPLEMENTATION.md)에 상세 범위와 검증 한계를 기록했습니다.
